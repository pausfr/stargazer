# Functional Design Questions — u3-domain-rules

> 단위 U3 u3-domain-rules (library): 달력(주말·공휴일 연휴 날짜 산출) + 추천 판정(관측 좋은 날). C3 계약(listCandidateDates, recommend)·requirements(FR1·FR2)·메모리 결정을 바탕으로, 아직 열린 것만 질문합니다. 이미 정해진 것(추천=달 조도 낮음 AND 구름 적음, 예보 없는 날은 조도만, 잠정 임계값 조도≤20%·구름≤30%, "그날 밤"=KST 저녁~다음날 새벽, 3개월 범위)은 다시 묻지 않습니다.

## Q1. 한국 공휴일 데이터 소스
`listCandidateDates`가 공휴일 연휴를 산출하려면 한국 공휴일 날짜가 필요합니다. 어떻게 할까요?
- A. 코드에 공휴일 규칙/날짜 테이블을 내장(법정공휴일 + 대체공휴일 규칙을 하드코딩, 네트워크 없음). 무료·키 불필요·오프라인 안전. 매년 수동 갱신 필요.
- B. 무료 공휴일 API(키 불필요)를 호출해 가져온다. 최신성 좋음, 그러나 정적 앱·오프라인 전제·무료 한도 고려 필요.
- C. 하이브리드: 내장 테이블을 기본으로 하되, 다음 버전에서 API 보강 여지만 열어둠(MVP는 내장).

[Answer]: A. 코드에 공휴일 테이블 내장. 추가 요구: 테이블이 커버하는 연도 범위를 명시하고, 범위 밖 날짜의 처리 방식(공휴일 정보 없이 주말만 판정)을 rules에 적는다.A

## Q2. 추천 임계값 최종 수치 (FR2.4)
잠정값은 "달 조도 ≤ 20%(어두운 밤) AND 구름량 ≤ 30%"입니다. 이대로 확정할까요?
- A. 잠정값 그대로 확정(조도 ≤ 20%, 구름 ≤ 30%).
- B. 조정하겠다 — 원하는 수치를 적어 주세요(예: 조도 ≤ 25%, 구름 ≤ 40%).

[Answer]: A. 잠정값 그대로 확정 — 조도 ≤ 20%, 구름 ≤ 30%.A

## Q3. "연휴"(연속 휴일) 묶음 규칙
주말·공휴일이 연속될 때 카드를 어떻게 묶을까요?
- A. 연속된 주말+공휴일을 하나의 "연휴" 카드로 묶고, 그 묶음의 각 밤을 모두 후보로 둔다(라벨은 묶음 이름, 예: "추석 연휴").
- B. 날짜별로 개별 카드(묶지 않음). 각 밤이 독립 카드.
- C. 연휴는 묶되 카드 안에서 밤별로 펼쳐 보여줄 수 있게 묶음+개별 밤 둘 다 제공(U4가 선택).

[Answer]: A. 연속된 주말+공휴일을 하나의 "연휴" 카드로 묶고, 묶음의 각 밤을 모두 후보로 둔다(라벨은 묶음 이름).A

## Q4. deferred(판단 보류) 날짜의 정렬·표시
예보 범위 안인데 구름 데이터가 unknown이면 verdict=deferred입니다(C3). 목록에서 어떻게 다룰까요?
- A. 제외하지 않고 목록에 남기되 추천/비추천 뒤로 정렬(달 조도는 보여주고 구름은 "알 수 없음").
- B. 달 조도만으로 임시 판정해 recommended/not_recommended에 섞되 "구름 미확인" 표시.
- C. 기타(원하는 방식을 적어 주세요).

[Answer]: A. 제외하지 않고 목록에 남기되 추천/비추천 뒤로 정렬(달 조도는 보여주고 구름은 "알 수 없음"). rules에 "예보 범위 안 unknown = deferred"를 명시한다.A

## Q5. 후보 날짜 밤 단위 처리 (FR1.4, AC1.1.2)
"그날 밤"은 KST 저녁~다음날 새벽입니다(이미 결정). recommend는 AstronomyResult·CloudForecast를 받아 밤 단위로 판정하는데, CalendarDate가 밤 범위(nightStartKst/nightEndKst)를 들고 있으면 됩니다. 추가로 u1/u2 호출 조합(여러 좌표·여러 날짜)에서 U3가 챙겨야 할 특이 케이스가 있을까요?
- A. 없음 — 전국 대표 좌표 1점·날짜별 1밤으로 단순. C3 시그니처 그대로.
- B. 있음(적어 주세요).

[Answer]: A. 없음 — 전국 대표 좌표 1점·날짜별 1밤으로 단순, C3 시그니처 그대로. (추가 요구: rules에 "outOfHorizon = 달 조도만으로 추천 판정"을 명시한다.)A
