# User Flow — 별 보기 좋은 날 추천 앱

> 근거: intent-statement.md(핵심 흐름), scope-document.md, rough-mockups-questions.md.

## 핵심 흐름 (해피 패스)

```
Flow: 관측 좋은 밤 고르기
Persona: 나와 친구들 (취미 관측 경험자)
Trigger: 앱 URL 열기 (모바일)
Steps:
  1. [메인: 카드 목록] 로딩 -> 다가오는 3개월 연휴/주말 카드 표시(추천 날 노란 테두리 강조)
  2. [메인] 사용자가 카드를 훑어봄 -> 달 위상/날씨/추천 배지로 후보 가늠
  3. [메인] 좋아 보이는 카드 탭 -> [상세: 그래프] 화면으로 이동
  4. [상세] 이중축 그래프 + 완전한 밤 구간 + 월출·월몰로 그 밤을 판단
  5. [상세] 뒤로가기 -> [메인]으로 복귀, 다른 카드 탭해서 비교
Success outcome: "이 연휴 고민해볼까?" 수준의 판단을 내리고 앱을 닫음
Error paths:
  - 날짜/천문 데이터 로드 실패 -> [메인] 에러 상태 + "다시 시도"
  - 구름량(날씨) API 실패 -> 카드/그래프는 유지, 날씨 자리에 "날씨 불러오기 실패"(부분 상태)
  - 먼 날짜라 날씨 예보 없음 -> 에러 아님: "날씨는 날짜가 가까워지면" 안내로 구분
```

<!-- Text fallback: 사용자는 앱을 열어 3개월 치 연휴 카드 목록을 보고(추천 날은 강조됨), 좋아 보이는 카드를 눌러 상세 그래프 화면으로 간다. 그래프와 완전한 밤 구간·월출월몰로 그 밤이 관측에 좋은지 판단하고, 뒤로가기로 돌아와 다른 날과 비교한다. 데이터 로드 실패는 에러 상태로, 먼 날의 날씨 부재는 에러가 아닌 구분 안내로 처리한다. -->

## 흐름 다이어그램

```
[앱 열기]
    |
    v
[메인: 카드 목록] --(로드 실패)--> [에러 + 재시도]
    |
    | (카드 탭)
    v
[상세: 그래프] --(천문 계산 실패)--> [에러 + 재시도]
    |
    | (뒤로가기)
    v
[메인: 카드 목록] (다른 날 비교)
```
