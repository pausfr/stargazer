# Requirements — 별 보기 좋은 날 추천 앱 (첫 버전)

> 근거: intent-statement.md, scope-document.md, team-practices.md, 그리고 requirements-analysis 인터뷰(Q1~Q6). FR/NFR ID는 영구 추적 키이며 이후 단계가 그대로 보존한다.

## Intent Analysis

사용자(나와 친구들, 취미 관측자)가 시간 낼 수 있는 주말·공휴일 연휴 중 "별 보기 좋은 밤"을 빠르게 가늠하도록, 달 위상·구름·박명·월출몰을 한 화면에서 직관적으로 비교하게 한다. 목표는 완벽한 예측이 아니라 "이 연휴 고민해볼까?" 수준의 결정 지원이다. [intent-statement] [scope-document]

## Functional Requirements

### FR1. 연휴·주말 목록 (메인)
- FR1.1 시스템은 현재 시점부터 **3개월 이상** 앞의 주말과 한국 공휴일 연휴를 날짜순 카드 목록으로 보여준다. [scope-document]
- FR1.2 향후 3개월에 공휴일 연휴가 없으면 주말만이라도 목록에 표시한다. [Q3]
- FR1.3 각 카드는 날짜/연휴 이름, 달 위상 아이콘과 조도(%), 그리고 구름 예보 데이터가 있는 날이면 구름량 요약을 표시한다. [wireframes]
- FR1.4 "그날 밤"은 한국 표준시(KST) 기준 해당 날짜 저녁부터 다음날 새벽까지로 묶어 판단·표시한다. [Q6]

### FR2. 추천(관측 좋은 날) 강조
- FR2.1 시스템은 "추천"으로 판정된 날의 카드를 노란색 테두리와 별 아이콘·"추천" 라벨로 강조한다(색만으로 전달하지 않음). [wireframes] [project.md]
- FR2.2 **구름 예보 데이터가 있는 날**의 추천 판정은 달 조도가 낮고(어두운 밤) 구름도 적을 때 성립한다. 달은 어두워도 구름이 많으면 추천 강조를 제외한다. ("가까운/먼"을 미정의 날짜 경계가 아니라 "해당 날짜에 구름 예보가 존재하는가"로 판정해 경계값과 무관하게 검증 가능하게 한다.) [Q1] [Q2]
- FR2.3 **구름 예보 데이터가 없는 날**(예보 지평 밖)의 추천 판정은 달 조도만으로 한다(구름 조건은 예보가 생기면 적용). [Q1] [Q2]
- FR2.4 추천 판정의 구체 임계값은 설계/구현에서 수치화하되, 그때까지 테스트 가능한 기준을 위해 잠정 기본값으로 **달 조도 ≤ 20%를 "어두운 밤"**, **구름량 ≤ 30%를 "구름 적음"**으로 둔다(설계에서 조정 가능). [Q1] [assumption]

### FR3. 상세 그래프 (선택한 날)
- FR3.1 카드를 선택하면 그날 밤의 상세 그래프 화면으로 이동한다. [user-flow]
- FR3.2 상세 그래프는 x축=시간, 좌측 y축=달 밝기(조도 0~100%), 우측 y축=구름량(%)을 겹쳐 보여준다. [wireframes] [project.md]
- FR3.3 상세 그래프는 박명 구간(시민·항해·천문)을 음영으로, "완전한 밤"(저녁 천문박명 종료~새벽 천문박명 시작) 구간을 구분해 표시한다. [wireframes]
- FR3.4 상세 화면은 월출·월몰 시각과 완전한 밤 구간 시작·끝 시각을 핵심 숫자 요약으로 보여준다. [project.md] [wireframes]
- FR3.5 상세 화면은 각 선·음영의 의미를 설명하는 범례를 포함한다. [wireframes]
- FR3.6 상세에서 날짜 간 이동은 뒤로가기로만 한다(이전/다음 연휴 바로 이동은 첫 버전 제외). [project.md]

### FR4. 데이터: 천문 계산
- FR4.1 시스템은 전국 대표 좌표 하나를 기준으로 달 위상·조도, 박명(시민·항해·천문) 시각, 월출·월몰 시각을 계산한다. [scope-document] [project.md]
- FR4.2 달 밝기는 조도(illuminated fraction, 0~100%)로 표현한다. [project.md]

### FR5. 데이터: 날씨(구름량)
- FR5.1 시스템은 외부 무료 날씨 API로 구름량(운량) 예보를 받아 구름 예보 데이터가 있는 날짜의 카드·그래프에 표시한다. [scope-document] [project.md]
- FR5.2 구름 예보 데이터가 없는 날짜(예보 지평 밖)는 구름량을 표시하지 않고 "날씨는 날짜가 가까워지면 표시"로 구분한다. [feasibility-assessment] [project.md]
- FR5.3 데이터는 앱을 열 때 받아오고 짧게 캐시해 무료 한도를 보호한다. [project.md]

### FR6. 오류·경계 처리
- FR6.1 날씨 API 호출이 실패하면 달·박명·월출몰은 그대로 표시하고 구름 부분만 "불러오기 실패"로 표시한다(부분 상태). [Q3]
- FR6.2 천문 계산이 실패하면(드묾) 해당 카드/상세에 에러 메시지와 재시도 수단을 제공한다. [Q3]
- FR6.3 각 화면은 로딩·성공·에러·부분 상태를 구분해 표시한다. [wireframes]

## Non-Functional Requirements

- NFR1 (사용성/접근성) 기본 테마는 다크모드이며, 색만으로 정보를 전달하지 않도록 아이콘/라벨을 병행한다. 읽히는 수준의 글자 대비를 확보한다(가벼운 개인 앱 수준). [project.md] [team-practices]
- NFR2 (플랫폼) 모바일 세로 화면 우선으로 동작하며, 데스크톱에서도 깨지지 않고 넓게 표시된다. [scope-document] [wireframes]
- NFR3 (성능) 흔한 모바일 네트워크에서 메인 목록이 몇 초 내 표시된다(엄격한 정량 목표는 두지 않음). [Q4]
- NFR4 (가용성 모델) 온라인 사용을 전제로 하며, 오프라인 전용 동작은 지원하지 않는다(열 때 fetch + 짧은 캐시). [Q5]
- NFR5 (비용) 모든 런타임 데이터 소스는 무료 티어 범위 안에서만 사용한다. [project.md Mandated]
- NFR6 (보안) API 키 등 비밀값을 클라이언트 번들에 하드코딩하지 않는다. 정적 앱이라 키를 숨길 서버가 없으므로 키가 필요 없는 공개 API를 우선하고, 키가 필요하면 설계에서 프록시 여부를 정한다. [project.md Forbidden/Corrections]
- NFR7 (호스팅) 무료 정적 호스팅에 배포 가능한 클라이언트 중심 구조로 만든다. [team-practices Deployment]

## Constraints

- C1 전국 대표 좌표 하나로만 계산한다(지역 ~5구획 비교는 다음 버전). [scope-document]
- C2 무료 범위 운영, 무료 정적 호스팅, 클라이언트에서 계산·API 호출. [project.md] [team-practices]
- C3 시간 기준은 한국 표준시(KST) 고정. [Q6]

## Assumptions

- A1 추천 판정의 조도·구름 임계값은 설계/구현에서 수치화한다. [Q1]
- A2 사용할 무료 날씨 API와 그 예보 지평·운량 필드·무료 한도는 설계에서 확정한다. [feasibility]
- A3 천문 계산 라이브러리와 전국 대표 좌표의 구체 위치는 설계에서 확정한다. [feasibility]

## Out of Scope (첫 버전)

- 한국 ~5개 지역 구획 선택/비교(다음 버전), 먼 날짜 평년 기후값 추정, 즐겨찾기/개인화, 은하수·행성·유성우·별자리 비교, 계정/로그인·친구 공유·푸시 알림·과거 기록 저장, 상세의 이전/다음 연휴 바로 이동. [scope-document] [project.md]
