# Risk & Sequencing Rationale — 별 보기 좋은 날 추천 앱

> 근거: bolt-plan.md, unit-of-work-dependency.md, delivery-planning-questions.md(Q1·Q2·Q6), 사용자 채팅 요청.
> 이 문서는 Bolt 순서를 "왜 그렇게 정했는가"를 기록한다.

## 사용한 휴리스틱

**워킹 스켈레톤 우선(Cockburn)** + **위험 우선(risk-first)**의 조합. 공식 점수 모델(WSJF 등)은 쓰지 않았다(Q2=A) — 단위가 4개뿐이고 DAG(U1·U2 → U3 → U4)가 순서를 거의 강제하므로, 점수화의 비용 대비 가치가 낮다고 판단.

## 순서 근거

1. **Bolt 1을 워킹 스켈레톤으로 둔 이유(Q1=A, 사용자 명시 요청)**: 이 앱은 "계산(U1) → 도메인 규칙(U3) → 화면(U4)"의 모듈 호출 사슬과 정적 번들 구동이 핵심 통합 경로다. 가장 얇은 수직 슬라이스(달 조도 → 단순 추천 → 카드 1개)를 먼저 세우면, 조각들이 실제로 연결되는지와 화면 초안을 가장 먼저 확인할 수 있다. 날씨(U2)는 이 통합 경로의 필수가 아니므로 스텁으로 대체해 슬라이스를 얇게 유지한다.

2. **Bolt 2를 날씨 연동으로 둔 이유(위험 우선, Q6=A)**: 사용자가 꼽은 최대 위험은 "무료 날씨 API의 무료 한도·예보 지평·실패 처리가 설계대로 동작하는가"다. 스켈레톤이 돌아가는 즉시, 이 가장 불확실한 외부 경계(C4 어댑터, 3-상태 정규화)를 두 번째로 검증한다. 여기서 문제가 드러나면 아직 나머지 기능을 얹기 전이라 수정 비용이 작다.

3. **Bolt 3을 기능 완성으로 둔 이유(가치 완성)**: 통합 경로와 최대 위험이 모두 증명된 뒤, 박명·월출몰·이중축 그래프·전체 목록·상태 처리 등 나머지 기능을 얹어 "3개월 연휴 비교" 핵심 가치를 완성한다.

## DAG 위상 순서로부터의 편차

- 편차: U2(날씨)는 U1과 동급의 독립 단위지만 Bolt 2(두 번째)로 미뤘다. 순수 위상 순서라면 U1·U2가 함께 앞에 올 수 있다.
- 정당화: 워킹 스켈레톤을 먼저 세우기 위함(사용자 요청). U2는 스텁 인터페이스(contract C2 준수)로 대체되므로 U3·U4의 의존은 충족되고, 실제 U2는 Bolt 2에서 스텁을 교체한다. 런타임 단위 DAG 자체는 바뀌지 않으며, 이는 bolt-plan의 경제적 순서일 뿐이다.

## 리스크 요약

| 리스크 | 심각도 | 완화 (어느 Bolt에서) |
|--------|--------|----------------------|
| 무료 날씨 API 한도·예보 지평·실패 처리 | 높음 | Bolt 2에서 조기 검증, 3-상태 정규화·캐시로 격리 |
| 모듈 호출 사슬·정적 번들 통합 | 중간 | Bolt 1 스켈레톤에서 가장 먼저 증명 |
| 천문 계산 정확도(달 조도·박명·월출몰) | 중간 | 핵심 계산 모듈 ~80% 커버리지 테스트(team-practices), Bolt 1·3에 걸쳐 |
| 이중축 그래프 UI 렌더링 | 낮음~중간 | Bolt 3, 수동 스모크 보완 |
